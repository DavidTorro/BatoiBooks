# 5.1. Test - DOM

En esta práctica deberás **crear los tests de la vista y del controlador**.

Mantén los tests de las prácticas anteriores y adapta los que utilizan `getUserById()`, ya que ahora es asíncrono y requiere `await`.

## Herramientas y preparación

Utiliza **Vitest** para ejecutar las pruebas, **jsdom** para simular el DOM y **MSW** para simular las respuestas del servidor.

Instala jsdom como dependencia de desarrollo:

```sh
npm install -D jsdom
```

Crea `test/view.test.js` y `test/controller.test.js`. Añade al principio de ambos archivos:

```js
// @vitest-environment jsdom
```

Antes de cada prueba, prepara el HTML necesario y crea los objetos que vayas a utilizar. Recuerda que los elementos deben existir antes de instanciar la vista. No importes `main.js`, porque también inicia la aplicación.

## Pruebas que debes realizar

### Vista

- El desplegable muestra los módulos recibidos.
- Las tarjetas muestran los datos de los libros.
- Al actualizar el listado no se duplican las tarjetas.
- Los mensajes se muestran y pueden cerrarse; los informativos desaparecen a los tres segundos y los errores permanecen.
- Al enviar el formulario, el callback recibe los datos con los tipos adecuados.
- Al restablecer el formulario, se limpian los campos sin eliminarlo.
- Al solicitar una eliminación, el callback recibe la ID. Si está vacía, se muestra un error.

### Controlador

- La inicialización carga los datos y solicita que se muestren.
- El alta guarda el libro, actualiza la vista y restablece el formulario.
- La eliminación actualiza el listado.
- Los errores se comunican a la vista y no se muestran confirmaciones de éxito.

### Modelo

- `getUserById()` obtiene un usuario del servidor sin necesitar un `populate()` previo.
- Si el usuario no existe, la promesa se rechaza.

## Orientaciones

- Utiliza `beforeEach()` para que las pruebas sean independientes.
- Emplea `vi.fn()` para comprobar los callbacks y `vi.spyOn()` para simular métodos y comprobar sus llamadas.
- Simula clics y envíos del formulario para probar los eventos.
- Para los mensajes temporizados, utiliza los temporizadores simulados de Vitest.
- Reutiliza los manejadores de MSW de la práctica de Ajax. Los tests no deben depender del servidor real.
- Comprueba la estructura y el comportamiento del DOM; el aspecto visual se revisará en el navegador.

## Ejecución y entrega

Ejecuta las pruebas con:

```sh
npm run test -- --run
```

Entrega los tests junto con el proyecto y una captura del resultado. Cada prueba debe tener un nombre descriptivo y comprobaciones con `expect()` que permitan detectar errores.
